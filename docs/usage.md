## 1 · พนักงานแพ็ค

### ตอนเริ่มกะ

เปิดหน้าต่างอัดไว้ **1 ครั้งต่อกะ** แล้ววางไว้มุมจอ

```
https://pack.digital.in.th/rec.html
```

**ห้ามปิดหน้าต่างนี้ระหว่างกะ** — ปิดเมื่อไรโต๊ะนี้หยุดอัดทันที และคลิปที่กำลังอัดอยู่จะไม่สมบูรณ์

เปิดแล้วต้องเห็นภาพจากกล้องและมุมขวาบนขึ้นว่า **พร้อม**

### ขั้นตอนแพ็ค

ทำเหมือนเดิมทุกอย่าง **เพิ่มแค่สแกนบาร์โค้ดบนกล่องตอนแปะใบปะหน้าเสร็จ**

```
1. สแกน IMEI            →  หน้าต่างอัดขึ้น ● กำลังอัด
2. หยิบของ ใส่กล่อง ปิดกล่อง
3. แปะใบปะหน้า
4. สแกนบาร์โค้ดบนกล่อง   →  หน้าต่างอัดกลับเป็น พร้อม  ✅ เสร็จ
```

ขั้นที่ 4 คือขั้นที่เพิ่มมา ใช้เวลาประมาณ 2 วินาที **สแกนที่ช่องเดิมที่ใช้สแกน IMEI**

### ความหมายของสิ่งที่เห็น

| เห็นอะไร | แปลว่า | ต้องทำอะไร |
|---|---|---|
| **พร้อม** | ว่าง รอสแกนออเดอร์ถัดไป | — |
| **● กำลังอัด** | กำลังบันทึกอยู่ | แพ็คตามปกติ |
| 🔴 **ใบปะหน้าไม่ตรงกับออเดอร์** + เสียง | **แปะใบปะหน้าผิดกล่อง** | หยุด ตรวจว่ากล่องนี้ควรเป็นออเดอร์ไหน |
| **ดิสก์เต็ม — หยุดบันทึกชั่วคราว** | ที่เก็บเต็ม | แพ็คต่อได้ตามปกติ แจ้งหัวหน้า |
| **กล้องหลุด** | สาย USB หลุด | เสียบใหม่แล้วรีเฟรชหน้านี้ |
| **คิว** มีตัวเลขค้างนานๆ | เน็ตมีปัญหา | แพ็คต่อได้ คลิปไม่หาย แจ้งหัวหน้า |

### สแกนบาร์โค้ดไม่ติด

ใบปะหน้าบางใบพิมพ์ไม่ชัด สแกนยังไงก็ไม่เข้า → กด **ปิดคลิปเอง** ค้างไว้ 1 วินาที

ปุ่มนี้ต้องกดค้างเพื่อกันกดโดนตอนหยิบของ · ใช้บ่อยๆ ได้ไม่ผิด แต่ถ้าเจอทุกวันให้แจ้งหัวหน้า
เพราะเป็นปัญหาที่เครื่องพิมพ์ ไม่ใช่ที่ระบบ

### สิ่งที่ควรรู้

- **ไม่มีการบันทึกเสียง** ทุกกรณี และไม่มีปุ่มให้เปิด
- กล้องจับพื้นที่โต๊ะเป็นหลัก ไม่ได้เล็งใบหน้า
- คลิปเก็บไว้ 30 วันแล้วลบอัตโนมัติ ยกเว้นออเดอร์ที่มีเคส
- **ระบบวิดีโอล่มไม่กระทบการแพ็ค** — สแกนและพิมพ์ใบปะหน้าได้ตามปกติเสมอ

## 2 · หัวหน้าคลัง

```
https://pack.digital.in.th/monitor.html
```

รีเฟรชเองทุก 10 วินาที เปิดค้างไว้บนจอได้

### ดูอะไร

| การ์ด | ปกติควรเป็น | ถ้าผิดปกติ |
|---|---|---|
| **คลิปต่อใบปะหน้า** | ≥ 95% | มีการแพ็คที่ไม่ได้อัด — ดูตารางว่าโต๊ะไหน |
| **โต๊ะที่ต่ออยู่** | ครบทุกโต๊ะที่ทำงาน | โต๊ะที่หายไปไม่ได้อัด ให้ไปเปิดหน้าต่างอัด |
| **ดิสก์** | < 75% | ถึง 90% ระบบหยุดอัดเอง แจ้ง IT |
| **บันทึกได้ไหม** | ได้ | ไม่ได้ = ดิสก์เต็มหรือเขียนไม่ได้ |

### แถวสีแดงในตาราง

**โต๊ะนั้นกำลังแพ็คของอยู่แต่ไม่ได้อัด** — เป็นเคสที่ต้องรีบที่สุด ไปดูที่โต๊ะเลย
สาเหตุที่พบบ่อยคือพนักงานเผลอปิดหน้าต่างอัด

### ตัวเลขที่ใช้คุยกับทีม

| ตัวเลข | บอกอะไร |
|---|---|
| **อัตรา** รายโต๊ะ | โต๊ะไหนแพ็คโดยไม่ได้อัดบ่อย |
| จำนวน **เตือนใบปะหน้าผิด** | คนไหนแปะผิดบ่อย — เป็นเรื่องที่ต้องคุย ไม่ใช่แก้โปรแกรม |
| สัดส่วน **ปิดคลิปเอง** | สูง = เครื่องพิมพ์ใบปะหน้ามีปัญหา ไม่ใช่วินัยพนักงาน |

> ตัวเลขเหล่านี้มีไว้คุยเรื่องขั้นตอนหน้างาน ไม่ใช่ตัวชี้วัดผลงานรายคน
> วัตถุประสงค์ที่แจ้ง PDPA ไว้คือการเก็บหลักฐาน

## 3 · ทีม CS / เคลม

### ค้นหาคลิป

```
GET /api/search?q=<เลขอะไรก็ได้>
```

วางเลขอะไรก็ได้ลงไปตัวเดียว — **ordersn, เลขพัสดุ, IMEI** ระบบแยกให้เอง
มีขีดคั่นหรือช่องว่างติดมาก็ได้ ตัดให้เอง

กรองเพิ่มได้: `station` · `packer` · `status` · `pinned=true` · `from` / `to` (รูปแบบ `2026-08-01`)

### ผลที่ได้บอกอะไร

| `status` | ความหมาย |
|---|---|
| `verified` | ✅ สมบูรณ์ที่สุด — มีภาพเลขพัสดุในคลิป ใช้สู้เคสได้เต็มที่ |
| `manual_stop` | พนักงานปิดเอง (บาร์โค้ดสแกนไม่ติด) คลิปยังใช้ได้ |
| `unverified` | ไม่ได้ปิดตามขั้นตอน อาจไม่มีภาพเลขพัสดุ |
| `timeout` | ไม่มีความเคลื่อนไหวจนระบบปิดเอง |

ถ้า `media_available` เป็น `false` แต่มี `media_deleted_at` แปลว่า **เคยมีแต่ถูกลบตามกำหนด 30 วัน**
ไม่ใช่ระบบพัง

### ส่งหลักฐานเข้าแพลตฟอร์ม

แพลตฟอร์มรับวิดีโอ **≤ 60 วินาที และ ≤ 30 MB** เท่านั้น และ **ส่งผ่าน API ไม่ได้**
ต้องดาวน์โหลดแล้วอัปเข้า Seller Center เอง

```
POST /api/clips/<clip_id>/export
     { "by": "ชื่อคุณ" }
```

ได้ `download_url` กลับมา ไฟล์ที่ได้:

- ตัดมาแล้ว ≤ 60 วินาที ช่วงที่ครอบคลุมตอนปิดกล่องและเลขพัสดุ
- **มีวันเวลา + ordersn + เลขพัสดุ เบิร์นติดในภาพ**
- ไม่มีเสียง

**อยากเลือกช่วงเอง** ส่ง `start_ms` มาด้วย เช่น `{"start_ms": 30000}` = เริ่มที่วินาทีที่ 30

> ระบบให้เลือกได้แค่ **ช่วงเดียวต่อเนื่อง** โดยตั้งใจ — หลักฐานที่ตัดต่อจากหลายช่วง
> เสียน้ำหนักทันที ระบบจึงไม่เปิดช่องให้ทำ

### เมื่อแพลตฟอร์มขอเป็นรูป

TikTok บางเคสบังคับขอ "หลักฐานการแพ็คสินค้าก่อนจัดส่ง" เป็นรูปนิ่ง

```
GET /api/clips/<clip_id>/frame?at_ms=15000
```

ได้ไฟล์ JPG ที่มีวันเวลาเบิร์นเหมือนวิดีโอ · ขอได้สูงสุด 6 รูป

**Lazada เคสคืนเงิน** ต้องมีรูปปกคู่กับวิดีโอ → `GET /api/clips/<clip_id>/cover`

### ส่งลิงก์ให้ลูกค้า / ขนส่ง

```
POST /api/clips/<clip_id>/share
     { "by": "ชื่อคุณ", "note": "ส่งให้ Flash เคลมของหาย", "days": 7 }
```

ได้ลิงก์ที่:

- เปิดดูได้เลยบนมือถือ ไม่ต้องล็อกอิน
- **หมดอายุตามที่ตั้ง** (ปริยาย 7 วัน สูงสุด 90)
- ดูได้เฉพาะคลิปนั้นคลิปเดียว
- นับได้ว่าถูกเปิดกี่ครั้ง เมื่อไร

**ยกเลิกทันที** เมื่อไม่ต้องการแล้ว:

```
DELETE /api/share/<token>   { "by": "ชื่อคุณ" }
```

ยกเลิกแล้วคนที่เปิดค้างไว้ก็ดูต่อไม่ได้ทันที

> ⚠️ ลิงก์นี้ทำให้ข้อมูลออกนอกองค์กร ตั้งอายุให้สั้นที่สุดเท่าที่พอใช้งาน
> และยกเลิกเมื่อจบเรื่อง · ดูได้ว่าคลิปไหนถูกส่งให้ใครไปแล้วบ้างที่ `/api/clips/<id>/shares`

### กันคลิปไม่ให้ถูกลบ

คลิปทั่วไปถูกลบเมื่อครบ 30 วัน **ถ้าเคสยังไม่จบให้ตรึงไว้**

```
POST /api/clips/<clip_id>/pin   { "by": "ชื่อคุณ", "note": "เคส #12345" }
```

ระบบตรึงให้อัตโนมัติอยู่แล้วเมื่อ:
- RefundCases เปิดเคสของออเดอร์นั้น
- คลิปปิดแบบ `unverified` หรือ `timeout`
- เคยเตือนใบปะหน้าไม่ตรง

**ตรึงด้วยมือเมื่อ** เคสมาทางแชทหรืออีเมลก่อนที่จะเปิดเคสในระบบ — อย่ารอ เพราะพอครบ 30 วันแล้วไม่มีอะไรกู้คืนได้

## 4 · ผู้ดูแลระบบ

### ตรวจสุขภาพ

```
GET /api/health
```

ตอบ `200` เมื่อปกติ · `503` เมื่อ Mongo ต่อไม่ได้หรือเขียนดิสก์ไม่ได้

ดูอะไรบ้าง: `mongo` · `storage` (พื้นที่ ระดับ เขียนได้ไหม) · `ffmpeg` (ส่งออกหลักฐานได้ไหม)

```bash
BASE=https://pack.digital.in.th npm run smoke
```

### การแจ้งเตือนที่จะได้รับ

| เตือนว่า | ควรทำ |
|---|---|
| อัตราคลิปต่อใบปะหน้าต่ำ | บอกหัวหน้าคลัง ดูว่าโต๊ะไหน |
| โต๊ะพิมพ์ใบปะหน้าแต่ไม่มีเครื่องต่อ | **เร่งด่วน** ไปเปิดหน้าต่างอัดที่โต๊ะนั้น |
| ไม่ได้รับสัญญาณเลยเกิน 15 นาที | `hook.js` อาจพัง — เช็คว่า script tag ยังอยู่ในหน้าแพ็ค |
| ดิสก์ 75% / 85% / 90% | ที่ 90% ระบบหยุดอัดเอง งานแพ็คยังเดินต่อ |
| ต่อฐานข้อมูลไม่ได้ | ระบบยังรับสัญญาณแต่ไม่อัด |

เรื่องเดิมเตือนซ้ำได้ทุก 30 นาที ไม่สแปม

### งานลบข้อมูลตามกำหนด

ทำงานเองตอนตี 2 ทุกวัน · ลบคลิปที่เกิน `RETENTION_DAYS` ยกเว้นที่ตรึงไว้

**สั่งซ้อมด้วยมือ** (ไม่ลบจริง):

```bash
curl -X POST https://pack.digital.in.th/api/retention/run -H 'Content-Type: application/json' -d '{}'
```

**สั่งลบจริง** ต้องส่ง `confirm`:

```bash
curl -X POST https://pack.digital.in.th/api/retention/run -H 'Content-Type: application/json' -d '{"confirm":true}'
```

> งานนี้ **ยอมไม่ลบดีกว่าลบผิด** — ถ้าย้ายคลิปที่ตรึงไว้ไม่ครบ มันจะข้ามทั้งวันนั้น
> ไม่ลบอะไรเลยแม้แต่คลิปที่ไม่ได้ตรึง แล้วแจ้งเตือน

### แก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุที่พบบ่อย | แก้ |
|---|---|---|
| หน้าต่างอัดขึ้น "ขาดการเชื่อมต่อ" ตลอด | nginx ไม่ได้ตั้ง `proxy_buffering off` ที่ `/api/stream/` | ดู [install.md §6](install.md) |
| ตัวอัดหลุดทุก 60 วินาที | `proxy_read_timeout` สั้นไป | ตั้งเป็น `1h` |
| ใบปะหน้าเพิ่มแต่คลิปไม่เพิ่ม | หน้าต่างอัดไม่ได้เปิด หรือกล้องเปิดไม่ได้ | เปิด `/rec.html` ดู warning บนหน้า |
| ไม่มีสัญญาณเข้ามาเลย | script tag หาย หรือ `ALLOWED_ORIGINS` ผิด | เช็ค 2 ไฟล์ใน sellcenter |
| ส่งออกหลักฐานไม่ได้ | `ffmpeg` ไม่มี `drawtext` | ดู `/api/health` ช่อง `ffmpeg` — สร้าง image ใหม่ |
| เลื่อนดูกลางคลิปไม่ได้ | nginx ไม่ส่ง `Range` ผ่าน | ดู [install.md §6](install.md) |
| คลิปไม่ขึ้นทันทีหลังสแกน | ปกติ — คลิปปรากฏหลังปิดแล้ว | — |

### สำรองข้อมูล

**คลิปทั่วไปไม่ต้องสำรอง** — เป็นข้อมูลชั่วคราว 30 วัน HDD พังยอมรับได้

**`_pinned/` ต้องสำรอง** — คือหลักฐานของเคสที่กำลังสู้เงินอยู่ และเล็กมาก
(เคสจริงไม่ถึง 1% ของออเดอร์ ≈ 170 MB/วัน หรือ ~62 GB/ปี)

```bash
rsync -a --delete /mnt/packvideo/_pinned/ /path/to/backup/packvideo_pinned/
```

ตั้ง cron ให้ทำทุกคืน และ **ทดสอบกู้คืนจริงอย่างน้อย 1 ครั้ง** ก่อนเชื่อว่าใช้ได้
