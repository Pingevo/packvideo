## 3. ความต้องการ

### R1 · เตือนเมื่อไม่ได้บันทึกจริง (P0) — แก้ F1–F3

- **R1.1** คลิปเปิดแล้ว **ไม่มีชิ้นวิดีโอถึงเซิร์ฟเวอร์ภายใน N วินาที** (เสนอ 5) = สถานะ "ไม่ได้บันทึก"
- **R1.2** หน้าแพ็คใน sellcenter แสดงเตือน **เต็มแถบบนสีแดง + เสียง** ที่มองเห็นได้ขณะก้มแพ็ค ข้อความบอกว่าต้องทำอะไร เช่น "กล้องโต๊ะ desk-02 ไม่ได้บันทึก — เปิดหน้าต่างอัด"
- **R1.3** เตือนค้างจนกว่าวิดีโอจะกลับมาจริง ไม่หายเองเมื่อเริ่มออเดอร์ถัดไป
- **R1.4** ไม่ล็อกงานแพ็ค (หลักการ "งานแพ็คห้ามหยุด" ยังอยู่)
- **R1.5** ตั้งแต่ออเดอร์แรกของวัน: ถ้าโต๊ะนั้นไม่มีหน้าต่างอัดต่ออยู่ ต้องเตือนก่อนเริ่มแพ็ค (สาเหตุ A2)
- **R1.6** พนักงานไปแพ็คโต๊ะคนอื่น: หน้าแพ็คต้องบอกชัดว่า **กำลังใช้โต๊ะไหน และกล้องของโต๊ะนั้นเปิดอยู่ไหม** (F3)
- **R1.6a** ตอนเริ่มกะ (ออเดอร์แรกของบัญชีนั้นในวัน หรือเมื่อบัญชีที่ล็อกอินต่างจากคนล่าสุดของโต๊ะ) ให้ถามยืนยันโต๊ะ 1 ครั้ง พร้อมแสดงภาพสดจากกล้องโต๊ะนั้น — ยืนยันแล้วไม่ถามซ้ำทั้งวัน · ไม่ยืนยันก็แพ็คต่อได้ แต่แถบเตือนค้าง
- **R1.7** คลิปว่างติดกัน ≥3 คลิป แจ้งหัวหน้าคลัง **ทั้ง Telegram และการ์ดบนหน้า /work ของ sellcenter**
  - ข้อความบอก โต๊ะ · พนักงาน · เริ่มดับกี่โมง · กี่ออเดอร์แล้ว
  - แจ้งครั้งเดียวต่อช่วงดับ + แจ้งอีกครั้งเมื่อกลับมาบันทึก (ไม่ spam ทุกคลิป)
  - ผู้รับ Telegram ตั้งผ่าน environment ได้ภายหลัง — ยังไม่ตั้งก็ต้องไม่พัง
  - การ์ด /work นับ "ออเดอร์วันนี้ที่ไม่มีวิดีโอ" แยกโต๊ะ

**เกณฑ์ผ่าน**
- ปิดหน้าต่างอัดระหว่างกะ → หน้าแพ็คขึ้นแดงภายใน 10 วินาที
- ถอดกล้อง → ขึ้นแดงภายใน 10 วินาที
- วันเดียวกัน ไม่มีช่วงคลิปว่างติดกันเกิน 3 คลิปโดยไม่มีการเตือน

### R2 · คลิปต้องครบ (P0) — แก้ F5, F6

- **R2.1** วิดีโอช่วงยิงบาร์โค้ดปิดกล่องต้องอยู่ในไฟล์ (ความยาวไฟล์ ≥ เวลาที่อัด − 0.5 วิ)
- **R2.2** checksum ยังต้องล็อกไฟล์หลังปิดสมบูรณ์ (หลักฐานแก้ไม่ได้)
- **R2.3** สัญญาณเริ่มซ้ำภายใน 2 วิ ต้องไม่สร้างคลิปว่างแยกอีกตัว

### R3 · ล็อกอินด้วย sellcenter (P0) — แก้ F7, F11

- **R3.1** ทุกหน้าและ API ยกเว้น `/s/<token>`, `/signal`, `/hook.js`, `/api/health` ต้องล็อกอินด้วยบัญชี sellcenter
- **R3.2** `/media/:id` ต้องตรวจสิทธิ์เหมือน API
- **R3.3** ชื่อผู้ทำรายการ (ส่งออก ตรึง สร้างลิงก์) มาจากบัญชีที่ล็อกอิน เลิกใช้ `prompt()`
- **R3.4** หน้าต่างอัด (rec.html) เปิดค้างทั้งกะ — session ต้องไม่หมดกลางกะแล้วทำให้หยุดบันทึก
- **R3.5** ไม่แยกบทบาท — ผู้ที่ล็อกอิน sellcenter ได้ทุกคนใช้ได้ทุกฟังก์ชัน แต่ต้องบันทึกชื่อผู้ทำทุกครั้ง (ประวัติคือตัวคุม)

**แก้ข้อมูล (ตรวจโค้ดแล้ว):** cookie `token` ของ sellcenter ตั้ง `domain=.digital.in.th` (AuthenController) และเป็น JWT HS256 — pack.digital.in.th ได้รับ cookie นี้อยู่แล้วและตรวจลายเซ็นเองได้ ไม่ต้องมีทางส่งต่อตัวตน · ข้อความเดิมที่ว่าเป็น memory store อ่านข้ามซับโดเมนไม่ได้นั้นผิด

### R4 · หน้าค้นหาคลิปใช้ง่าย (P1) — แก้ F4, F8, F10

- **R4.1** คลิปไม่มีวิดีโอแสดงป้ายต่างชัดเจน 3 แบบ: "ไม่ได้บันทึก (กล้องไม่ทำงาน)" / "ลบแล้วตามกำหนด" / "มีวิดีโอ"
- **R4.2** สถานะเป็นภาษาไทย
- **R4.3** ตัวกรองวันที่ใช้ได้จริง (รวมคลิปเก่าที่ไม่มี `day`)
- **R4.4** กรองตามโต๊ะ พนักงาน และ "เฉพาะคลิปไม่มีวิดีโอ"
- **R4.5** เลื่อนหน้าดูผลเกิน 500 ได้
- **R4.6** ส่งออกผลค้นหาเป็น Excel (แทนไฟล์ที่ทำมือรอบนี้)
- **R4.7** ใช้บนมือถือได้ (CS เปิดจากโทรศัพท์)

### R5 · พนักงานแพ็คใช้งาน (P1)

- **R5.1** พนักงานแพ็คเปิดหน้าค้นหาคลิปได้เหมือน CS (เห็นทั้งหมด) · แผงบนหน้าต่างอัด (FR-12) ต้องเห็นคลิปว่างของโต๊ะตัวเองด้วย
- **R5.2** ตั้งเครื่องครั้งแรกเหลือขั้นตอนเดียว: เลือกโต๊ะ → เลือกกล้อง → **ทดสอบอัด 3 วิแล้วเห็นภาพที่อัปโหลดจริง**
- **R5.3** ปุ่ม "ทดสอบกล้อง" ใช้ได้ทุกเช้าก่อนเริ่มกะ

### R6 · หน้าสถานะระบบเชื่อถือได้ (P1) — แก้ F9

- **R6.1** ไม่มีการเตือนผิด: `hookdead` ต้องดูจากคลิปจริงในฐานข้อมูล ไม่ใช่ตัวนับในหน่วยความจำ

### 🔴 ไฟล์มีแต่เปิดไม่ได้ 324 คลิป (ออเดอร์จริง ~310) — สาเหตุเดียวกับท้ายคลิปหาย
- ตรวจหัวไฟล์ทุกคลิปที่มีวิดีโอ 6,221 คลิป: 5,868 ปกติ · **324 ขึ้นต้นด้วย `moof` แทน `ftyp`** (ไม่มีส่วนหัว เล่นไม่ได้ทุกโปรแกรม) · 29 ไฟล์หาย 404 (ทั้งหมดเป็นช่วงทดสอบ 11–18 ส.ค.)
- **320/324 (99%) เกิดเมื่อสแกนออเดอร์ใหม่ขณะคลิปก่อนยังเปิด** — และในกรณีนั้นเสีย 55% (320 จาก 587)
- กลไก (rec.html ทั้งเวอร์ชัน git และที่ deploy วันนี้):
  1. เซิร์ฟเวอร์ปิดคลิป A แล้วส่ง `stop` → หน้าต่างอัดสั่ง `recorder.stop()`
  2. ชิ้นสุดท้ายของ A ถูกปล่อยออกมา **แบบ async ทีหลัง**
  3. ถ้า `start` ของคลิป B มาถึงก่อน → `S.clipId = B`, `S.seq = 0` → ชิ้นท้ายของ A ถูกติดป้ายเป็น **B ลำดับ 0** → ไฟล์ B ขึ้นต้นด้วยข้อมูลของ A
  4. ถ้าไม่มี B มาแทรก ชิ้นท้ายของ A ถูกส่งไปหลังเซิร์ฟเวอร์ปิด A แล้ว → 409 → ทิ้ง → **ท้ายคลิปหาย (R2)**
- ต้นเหตุร่วม: `ondataavailable` อ่าน `S.clipId`/`S.seq` ตัวกลาง ณ เวลาที่ event เกิด ไม่ใช่ของ recorder ตัวที่ปล่อยชิ้นนั้น + เซิร์ฟเวอร์ปิดไฟล์ก่อนชิ้นสุดท้ายถึง
- **กู้ได้:** ตัดไบต์ก่อนกล่อง `ftyp` ตัวแรกออก ทดสอบสุ่ม 10 คลิป เล่นได้ครบ 9 (อีก 1 คลิปยาว 5.5 วิ เหลือภาพ 0.1 วิ)
- **R2.4 ใหม่:** ชิ้นวิดีโอต้องผูกกับคลิปของ recorder ที่ปล่อยมัน ไม่ใช่คลิปปัจจุบัน
- **R2.5 ใหม่:** เครื่องมือกู้ไฟล์ 324 คลิป — เขียนเป็น **ไฟล์กู้แยก** ไม่ทับต้นฉบับ (ต้นฉบับมี checksum เป็นหลักฐาน) และบันทึก clip_event ว่ากู้เมื่อไร
- **R6.4 ใหม่:** ตรวจหัวไฟล์ทุกคลิปตอนปิด ถ้าไม่ใช่ `ftyp` ติดธง `corrupt` และให้หน้าค้นหาแสดงต่างจาก "มีวิดีโอ"
